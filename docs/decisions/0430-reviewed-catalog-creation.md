# 0430. Review catalog creation before saving a new plan

Status: accepted agent decision. Verification evidence is recorded separately.

Extends0410 with one creation-only driver. The pure materializer remains the
authority for definitions, explicit permanent identities, scoped shared bindings,
final-ID source baselines and advisory preparation. Existing-plan editing,
retirement/reservations, outcome changes and invitation generation are separate.

Provide `onboard-kit catalog create --id ID --out FILE`. Its line-oriented draft
supports explicit add, bind, unbind, remove, review and cancel actions. Selection
and bindings exist in memory only. The lasting output is the ordinary encoded
plan, never a second selection manifest. Only save at the complete current
review publishes one new file; an existing or concurrently appearing destination
refuses. No overwrite option or default acceptance exists.

This first driver supplies an empty directory, no plan-variable declarations or
bindings, and zero provenance to the materializer. It supports every current
section source with unanswered facts allowed, including repeated repository and
reading activities. Organizational directory/plan-variable authoring remains
with existing explicit workflows; it is not inferred from personal preparation.
No context plan, personal record, preparation file, clock or environment identity
is read. A binding requiring an unknown directory target still fails the actual
materializer. No general readiness or invitation-readiness claim follows save.

Use literal text, flag, list and deferred binding forms. Unbind removes an
explicit draft key. Do not offer a stored None answer: the existing plan encoder
cannot represent it. This narrows the driver interaction without changing the
materializer or encoder contracts. Empty text/list and false remain explicit
values and are never treated as unbind or a missing action.

Removing an unsaved instance removes its scoped draft bindings. Reusing that ID
within the same never-published draft is allowed because no saved identity or
personal history exists. This is not retirement of a saved activity. Later
existing-plan editing must reserve held IDs and retain disabled definitions and
bindings under0410; this increment receives no existing plan and cannot do that
work implicitly.

The output parent already exists. Inspect safe paths without preconsent writes,
freeze exact real encoder bytes, display them and every actual advisory guide
with instance reasons, and publish those same bytes exclusively after save.
Use checked native paths, private publication controls and owned temporary
cleanup. Refusal before publication preserves every existing artifact. A
published file remains published even if cleanup or reporting fails.

P1/P3 favor explicit known shared facts and usable preparation advice. P2/0110/
0120 require deliberate identities, exact scopes, no silent defaults and no
overwrites. P4 bounds writes to a new reviewed file. P5 preserves offline compiled
sources; P6 keeps targets advisory. P7 limits context and private diagnostics;
P8 favors one bounded plain-text interaction and existing pure dependencies.
Typed CLI tuples and an external request manifest were considered: both add a
second user format and expose longer facts in command history. The chosen
interaction follows the existing preparation guide without adopting its edits
to existing files or its broader recipient/arrangement forms.

Declare catalog creator at position6, depending only on catalog materializer5,
plan encoder1, model and its own contract, plus standard/native filesystem
facilities. Binary8 routes the exact catalog create pair to it; other catalog
operations remain with command/catalog. The independent four-part contract pins
grammar, display, caps and publication. No passing checks or release delivery
are implied by this decision.
