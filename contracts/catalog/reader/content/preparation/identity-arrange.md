# Arrange company identity

Confirm the provisioning owner, approved account policy and request route.
Keep those shared facts in the plan. Preparation may carry a known company
email when useful, but its absence is not itself an invitation blocker.
Never store an initial password, recovery code or personal delivery address.

Track a person-specific provisioning request with the existing access kind
and an actual declared identity section instance. Use a stable unique id,
known owner and nonsecret request reference before claiming arranged. An access
item need not invent a helper when none is assigned. Missing details can stay
visible while pending, requested or deferred; an unknown supplied contact is
invalid rather than incomplete. Do not invent an identity-arrange kind.

Ensure activation and support instructions are usable before the account works.
Confirm any target date as a planning goal, not a deadline that fails someone.
Requested or arranged provisioning is not working authentication, confirmed
recipient identity, invitation import or first use. Verification belongs to
the newcomer's actual capability check, not this preparation status.
