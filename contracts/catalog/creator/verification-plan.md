# Independent verification plan

No execution evidence exists for this draft. Root first formats and compiles
the scratch contract, checks fixture framing against public contracts, and runs
the supplied zero stub. Every meaningful output/refusal/save assertion must fail;
compilation errors or timeout are not acceptable stub-red evidence. Fix fixture
defects independently before admitting any product implementation.

## Finite wrong controls

| Plausible wrong behavior | Authored independent observation |
| -- | -- |
| Return empty success | Literal help, reports, startup and exact saved plan |
| Save at startup or on EOF | Cancel, partial save, draft-save and review-back cases |
| Buffer queued save before displaying review | Review writer failures and counted input |
| Replace destination | Existing native path and concurrent exclusive publication |
| Publish stale different bytes | Complete empty golden and repeated full decoded plan |
| Reuse source ID as permanent ID | Independent final-ID canonical hash and four repeated instances |
| Collapse equal sources or share their answers | Full repeated plan map and scoped answers |
| Infer defaults or answers | Unanswered scopes, unbind and rejected-value cases |
| Lose explicit empty values | Empty text and empty contact list |
| Validate a private mirror instead of actual materializer | Nonexample repeated source, unknown source/name, wrong kind, carrier and duplicate cases |
| Print raw messages or suppress all repairs | Exact safe projection and private-input controls |
| Treat advisory preparation as completion | Review wording, relevant reasons, no personal writes |
| Leave consented temporary or change unrelated files | Native directory inventory and preservation checks |
| Read whole stream or accept partial final action | Counted input, complete CRLF, incomplete save and line/total caps |

Apply each wrong control in an independently owned disposable source copy and
record the concrete assertion failure, not merely a compile or timeout result.
Do not change these tests to match a candidate's output. After first source
freeze, admit judging fixtures, run native/race checks and mutation, and report
survivors as gaps rather than editing accepted lists.

## Remaining evidence obligations

The authored fixtures do not yet exhaust all supported native publication and
stream faults. Before durable contract approval, add independent native ACL
inheritance/unsupported-private-publication fixtures on supported platforms and
owned temporary close/cleanup failures. Parent replacement, post-publication
report failure, borrowed input/stdout nonclosure and exact advisory Markdown
display now have authored fixtures, but still require actual execution.
If a native precondition cannot be established, report a named platform gap;
never simulate successful privacy checks or strip ambient ACLs. No injectable
filesystem or semantic dependencies are authorized by this proposal.

Also independently exercise every numeric boundary on both sides (argv bytes,
anchored path, decoded ID/path, list count, encoded output and review expansion).
Input n+EOF/n+error/zero-progress now have authored fixtures. Existing cap
fixtures are not complete boundary proof. Root should decide whether these need
additional fixture increments before implementation proceeds.

Binary data proposals cover routing/discovery, complete review, no overwrite,
cancel and preservation, plus an ordinary assembled plan from repeated sources.
The repeated binary scenario intentionally delegates exact saved-plan structure
to independent unit literals; it does not claim that file existence or assembly
alone proves scoped identity preservation. The runner cannot inspect input
consumption, file modes, atomicity or every native fault.

Finally build a second implementation from this frozen contract without first
implementation access, and stream a bounded deterministic corpus through both.
Differences are investigations, not an output oracle or equivalence proof.
Include malformed grammar, all current sources, repeated identities, explicit
binding forms, cancellation/review boundaries and native context refusal cases.
