# People map

Build this in the first month. Use roles and names inside the client's copy of this doc. Keep it free of personal details beyond work context.

| Person | Role | Owns | Works with | Ask them about |
| --- | --- | --- | --- | --- |
| `<name>` | Onboarding owner | | | Expectations, priorities |
| `<name>` | Technical or design lead | | | How we build, how we decide |
| `<name>` | Product owner | | | What matters to users |
| `<name>` | Teammate | | | Day to day work |
| `<name>` | Stakeholder | | | What they need from the team |

## Questions that fill the map

- Who do you go to when you are stuck?
- Who decides when people disagree?
- Who knows the history of this system or product?
- Who is affected by the work but rarely in the room?
