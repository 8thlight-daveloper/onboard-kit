# Contributing

Improve these templates after an engagement, using what you learned. Keep them generic.

## Sanitizing rules

Before committing, check each change against these:

- No client or organization names, including in examples. Use `<Organization>` and `<Team>`.
- No real URLs, repo names, or tool tenants. Use `<link to ...>`.
- No names of client staff. Use roles: "the onboarding owner", "your tech lead".
- No figures, dates, or outcomes from a real engagement.

If a lesson only makes sense with the client's details attached, state the general pattern and leave the details out.

## Writing style

The client will read these templates, so write for a newcomer who has never heard of us.

- Plain words. Short sentences. Active voice.
- Imperative for steps: "Ask your lead who approves access."
- Sentence case headings.
- Placeholders go in angle brackets: `<Organization>`.
- One idea per checklist item.

## Adding a variant

Variants hold only what differs from `core/`. If a variant repeats core content, move that content to core. A new discipline (data, product management) is one new file in `variants/discipline/`.
